# 游戏性改进方案（提案稿）

> 状态：**提案，未实施**。本文档记录对「月面王国」游戏性的诊断与改进方案，供后续评审与排期。任何实施前需与当前规则文档（`docs/philosophy/`）对齐，且不得破坏既有数值平衡锚定（见 [economy-tuning.md](economy-tuning.md)）。

## 1. 现状盘点

现有已实现系统：

- 15 座设施 + 11 种资源的完整经济链，4 级难度（宽裕 / 常规 / 严峻 / 极限）。
- 科技树（建造许可 / 生产方式 / 效率修正 / 全局规则 / 贸易权限）。
- 8 个外星角色事件链（含分支与隐藏步骤），留任 / 派驻加成。
- 3 阶段御座号星舰建造终局目标。
- 王月报告（每 50 御日）、6 阶段指引、10 个里程碑日志。
- 5 档国祚评分（月面先驱 → 星海传奇）。
- 观察者模式（内置优化署自动执政）。
- 10 步新手教程。

## 2. 核心问题诊断

| 编号 | 问题 | 表现 |
|------|------|------|
| P1 | **决策密度过低** | 玩家设置设施方向后长时间被动等待，单局约 1 小时但大部分时间是"看自动播放"。 |
| P2 | **缺少负面事件** | 事件系统全部为外星访客（正面或中性），无危机、无意外、无失败风险。 |
| P3 | **短期目标缺失** | 只有每 50 御日的王月报告与 1000 御日的终局评分，中期缺乏明确导向。 |
| P4 | **叙事与玩法脱节** | 故事设定（被迫称王、密造御座号、SpaceZ 威胁、双足之禁）几乎未进入 gameplay。 |
| P5 | **重玩价值低** | 科技树、事件链、设施固定，各局体验高度相似，无局外进度。 |

## 3. 改进方案

### 3.1 随机危机事件系统（P0）

**目标**：填补 P1 / P2，制造张力与决策密度。

每间隔一定御日或按概率触发负面事件，提供 2-3 个应对选项（消耗资源缓解 vs 硬扛），或不可选项的持续惩罚。

候选危机（示例，数值待平衡）：

| 危机 | 效果 | 应对选项 |
|------|------|----------|
| 太阳风暴 | 电力产出 -30%，持续 10 御日 | 消耗星海货币购买防护 / 硬扛 |
| 月壤塌方 | C1/C2 采掘设施停工 5 御日 | 消耗合金加固 / 硬扛 |
| 生命维持泄漏 | 水、氧气消耗 +40%，持续 15 御日 | 消耗生物质封堵 / 硬扛 |
| 贸易船延误 | 星港贸易暂停 15 御日 | 消耗星海货币加急 / 等待 |
| 设备老化 | 随机设施维护消耗 +50% | 消耗知识检修 / 硬扛 |

**约束**：
- 危机强度与难度联动（easy 低概率低强度，ultimate 反之）。
- 观察者模式（L3 优化器）下由优化器按默认取向自动结算，不打断自动执政。
- 危机结束后可写入日志与王月报告，作为「本月大事」留存。

### 3.2 短期目标 / 任务系统（P0）

**目标**：填补 P3，给玩家「下一个王月该做什么」的明确导向。

王月报告中增加 2-3 个具体可量化目标，完成后即时发放小奖励：

示例：

- 「下个王月前将合金产量提升至 +8/御日」→ 奖励：知识 +15
- 「招募至少 2 名异客」→ 奖励：星海货币 +20
- 「完成科技 TR-0 研究」→ 奖励：解锁额外建筑槽位（或等价资源奖励）

**约束**：
- 目标由当前局面动态生成（参考优化器方向摘要 `summarizeOptimizerDirections` 的思路），不与优化器建议冲突。
- 奖励来源必须能从现有资源 / 科技规则追溯，不引入新资源。
- 观察者模式下自动完成并结算，仅写日志。

### 3.3 成就系统（P1）

**目标**：提升重玩动机（P5），在里程碑日志基础上扩展。

候选成就：

| 成就 | 条件 |
|------|------|
| 百人王座 | 首次达到 100 人口 |
| 群星来客 | 完成全部 8 条事件链 |
| 归乡在望 | 御座号完成度 ≥ 80% |
| 满朝文武 | 单局招募全部可招募角色 |
| 极限试炼 | 极限难度通关 |
| 自给自足 | 全程不使用贸易通关 |
| 御座竞速 | 500 御日内完成星舰 |

**约束**：
- 成就数据写入存档，终局结算（VictoryModal）与设置面板展示。
- 不提供属性加成，纯荣誉性，避免数值膨胀。

### 3.4 政策系统扩展（P1）

**目标**：填补 P4，扩展策略深度。

当前仅 `ration`（配给制）。提案扩展为 3-4 个政策，每个有明确利弊，切换有冷却期（如 50 御日）：

| 政策 | 效果 | 代价 |
|------|------|------|
| 配给制（ration，现有） | 生物质 +1 | 奢侈品产出 -50% |
| 全力生产（surge） | 所有产出 +15% | 设施维护消耗 +30% |
| 科研优先（research） | 研究速度 +40% | 工业产出 -15% |
| 开放贸易（open-trade） | 贸易收益 +25% | 战略物资可能外流 |

**约束**：
- 政策代码沿用现有 `policy: 'ration'` 字段模式扩展为联合类型。
- 修改 `docs/philosophy/technology-policy.md` 中的政策章节同步。

### 3.5 SpaceZ 敌对势力介入（P2）

**目标**：将故事设定中的 SpaceZ 变为实际 gameplay 元素（P4）。

- 中期（约 300 御日）触发 SpaceZ 发现月面繁荣，开始干扰。
- 表现形式：贸易封锁（星港价格恶化）、技术窃取（研究进度倒退）、人员策反（异客忠诚度下降）。
- 玩家选择：忍让（损失资源）、反击（消耗资源获得长期收益）、谈判（外交路线）。

**约束**：
- 作为事件链 / 危机系统的扩展实现，不新增独立系统。
- SpaceZ 仅在设定文档（`docs/philosophy/story.md`）已有设定的范围内展开，不新增与既有规则冲突的设定。

### 3.6 王座决策事件（P2）

**目标**：强化「当国王」的代入感（P4）。

在王城（Palace）视图中增加周期性「王座裁决」：叙事化的道德 / 外交取舍，影响人口、资源或后续事件。

示例：

- 「一批难民请求登陆月面。接纳将增加 5 人口但消耗 30 生物质；拒绝将获拓殖署嘉奖（+20 星海货币），但可能引发后续事件。」

**约束**：
- 复用现有事件链数据容器（`src/events/`），新增 `interaction` 类型需在 `src/events/types.ts` 登记并同步文档。
- 不改变现有角色 / 事件链的 ID、代号。

### 3.7 环境波动 / 周期性（P3）

**目标**：增加经济动态性（P1）。

太渊（气态巨行星）的潮汐与太阳活动周期影响殖民地，周期约 100 御日：

- 近地点 → 太阳能 +20%，但辐射增加 → 生命维持消耗 +10%。
- 远地点 → 太阳能 -15%，但月壤更稳定 → 采矿效率 +10%。

**约束**：
- 周期性变化应有 UI 提示（如资源栏角标或日志），避免被误解为 Bug。
- 幅度需在 `tests/simulation.test.ts` 1000 御日模拟中验证不破坏通关率。

### 3.8 跨局 Meta 进度（P3）

**目标**：长期重玩价值（P5）。

- 完成一局后解锁新难度、新设施变体、新事件链。
- 类似 Roguelite 的局外成长。

**约束**：改动面最大，需先行评估存档结构（`GameSaveState`）与开局门槛（`StartGate`）的兼容性。

### 3.9 稀有资源体系（后期目标）

**目标**：将量子计算核心与艺术奢侈品塑造为真正的「稀有战略物资」，解决后期大量溢出、缺乏消耗出口的问题。

**已落地部分**（2026-08-15）：
- 单位价值大幅上调：量子计算核心权重 150 → 320，艺术奢侈品 10 → 1600；对应下调产出数量（L ML-2、H MH-1），单件利润不变。
- 配方展示：稀有资源按 50 御日（王月）粒度显示产量并附时间标记（`/50御日`）；配方下方新增「本王月已产 / 配额」进度条（按当前配方 × 在岗 × 吞吐线性推算）。
- 星舰第三阶段（王座核心）新增艺术奢侈品投入（12，少量点缀），量子计算核心需求大幅上调（16 → 192），MD-3 每日输入同步，用于消耗后期量子核心产能。

**设计分工（后续迭代方向）**：
- **奢侈品**：主要消费方为**外星事件**（外交 / 满足特定文明需求），星舰仅作少量消耗。事件系统扩展时，奢侈品应作为事件选项的稀缺资源成本。
- **量子计算核心**：主要消费方为**高级建筑升级**（如归元装置、冠冕星舰坞扩建），星舰阶段次之。后续可让中后期建筑扩建逐步引入 QC 成本。

**约束**：
- 数值改动需保持既有配方利润不变（单件利润 = 产出 × 权重）。
- 展示改动遵循「样式架构」三类归属规则；新增类入组件模块 CSS，不污染全局。
- 实施前用 `tests/simulation.test.ts` 1000 御日模拟验证通关率基线不回归。

## 4. 实施优先级建议

| 优先级 | 改进项 | 预期效果 | 预估工作量 |
|--------|--------|----------|------------|
| P0 | 随机危机事件 | 立即增加紧张感与决策密度 | 中 |
| P0 | 短期目标任务 | 明确中期方向感 | 中小 |
| P1 | 成就系统 | 提升重玩动机 | 小 |
| P1 | 政策系统扩展 | 增加策略深度 | 中小 |
| P2 | SpaceZ 敌对势力 | 叙事与玩法统一 | 中 |
| P2 | 王座决策事件 | 强化国王代入感 | 中 |
| P3 | 环境波动 | 增加经济动态性 | 中 |
| P3 | 跨局 Meta 进度 | 长期重玩价值 | 大 |

## 5. 通用约束（所有方案适用）

- 不改 ID、code、代号、枚举值；不改既有数值平衡（资源 / 科技 / 建筑 / 事件奖励数值）。
- 新增文案遵循 PROJECT.md 品牌人格：冷峻、仪式化、有一点荒诞。
- 新增样式遵循「样式架构」三类归属规则（组件模块 CSS / shared.css / base.css + tokens.css）。
- 观察者模式（L3 优化器接管）下，一切新系统必须有自动化通道，不得强制打断自动执政。
- 每个方案实施前需评估对 `tests/simulation.test.ts`（1000 御日无事件模拟）的影响，保持通关率基线不回归。
