# 数值平衡与人均利润设计规范

> 本文档定义数值系统化的统一方法论。文档可能滞后，若与代码不一致，以 `src/economy/` 源码为准。

## 0. 核心假设：人口是唯一瓶颈

- 每个居民每日的维持消耗是确定的，它是全部经济数值的锚点。
- 每个居民通过劳动提供的「人均利润」决定殖民地的扩张速率。
- 殖民地扩张 = 人均利润 × 人口规模 − 维持成本；人口规模同时受住房容量与生命维持双重约束。

## 1. 统一价值基准

全项目只存在一套资源价值，即 `resourceWeights`（`src/economy/resources.ts`）。它是 `weightedValue`、优化器评分、GDP、星舰总价值与贸易价格的共同基准。

| 资源 | 权重 | 资源 | 权重 |
| --- | ---: | --- | ---: |
| 电力 | 1.0 | 量子计算核心 | 150.0 |
| 水 | 3.0 | 星海货币 | 1.0 |
| 氧气 | 3.0 | 人口 | 200.0 |
| 生物质 | 5.0 | 知识 | 8.0 |
| 月壤 | 2.0 | 艺术奢侈品 | 10.0 |
| 合金 | 8.0 | | |

贸易价格与权重直接挂钩：买入价 = 权重 ×（1 + 溢价），卖出价 = 权重 ×（1 − 折价）。

## 2. 人口维持成本（确定基准）

人口建筑的单位人口输入即维持成本，价值按第 1 节权重计算。

| 居民层级 | 建筑 | 输入（每人 / 御日） | 维持成本价值 |
| --- | --- | --- | ---: |
| 基础居民 | K 月面王城 | 水 0.4、氧气 0.3、生物质 0.3 | 3.6 |
| 宫廷居民 | H 翡翠宫 | 水 0.5、氧气 0.4、生物质 0.5 | 5.2 |
| 生态居民 | M 新月府 | 水 0.2、氧气 0.2、生物质 0.3 | 2.7 |

## 3. 人均利润分层（按科技时代）

人均利润 = `profitPerJob`（`src/economy/production.ts`）= 每岗产出价值 − 每岗消耗价值，含人口价值。

分层原则：

- 建筑按科技时代（`facilityEra`，`src/data/eraSections.ts`）归入早期 / 中期 / 晚期。
- 同一角色跨时代，人均利润递增：早期 < 中期 < 晚期。
- 同一建筑内，高级生产方式（`unlockedBy`）的人均利润高于默认生产方式。
- 能源建筑（E1 / E2 / E3）因电力权重低，人均利润天然低于工业 / 采掘，分层判断应在「能源角色」内部比较（E1 < E2 < E3），而非跨角色对齐。

具体数值以代码 `profitPerJob` 计算为准，不在此文档固化具体数字。

## 4. 人口建筑税收规则

- 所有人口建筑（K / H / M）都产出税收（星海货币），由 `projectPopulationSystem` 按实际入住人数结算。
- 税收价值必须低于维持成本价值，即「税收 − 维持成本 < 0」：人口本身是一种成本，其价值来自驱动的劳动利润，而非税收套利。
- 现状（按权重计算）：
  - K：税收 1.6 × 1 = 1.6 < 3.6 ✓
  - H：税收 1.6 × 1 = 1.6 < 5.2 ✓（另有艺术奢侈品 0.9，价值 9）
  - M：税收 1.2 × 1 = 1.2 < 2.7 ✓

## 5. 数值系统化三要素

任何配方调整必须同时满足：

1. **统一价值基准**：所有价值计算使用第 1 节 `resourceWeights`。
2. **确定的建筑科技**：每座建筑有唯一 era 归属，由 `requiredTech` 与 `facilityEra` 决定。
3. **人均利润分层**：调整结果必须通过第 3 节的分层审查。

## 6. 可调整参数（优先顺序）

数值失衡时，按以下顺序调整，而非直接重写配方：

1. 建筑升级扩张成本：`baseUpgradeCost` + `getUpgradeCostScale`（控制「扩一座建筑」的代价）。
2. D 冠冕星舰坞 / R 月穹生态环等巨大资源投入项目：阶段材料与建设阶段投入（控制终局与投资型建筑的资源黑洞）。
3. 生产方式配方 `input` / `output`：最后手段，调整后必须重新审计人均利润分层（第 3 节）。
