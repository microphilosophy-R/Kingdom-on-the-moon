# 经济参数调优笔记

## 基准锚定

以 1000 御日无事件模拟为基准，取 Day 200 累积合金利润 ~8260 作为成本校准锚点。

| 锚定指标 | 值 | 来源 |
|----------|-----|------|
| Day 200 合金库存 | 5774 | run-010.json |
| Day 200 累计建设消耗合金 | ~2500 | 85 项施工成本估算 |
| Day 200 累积利润 | **~8260** | 库存 + 消耗 - 初始 |

## 成本公式

```
cost = baseUpgradeCost × (level+1) × scale × levelTier × difficultyMult × discount
```

原版 `scale=4`（= jobsPerFacilityLevel），全部建筑升级总合金成本约 7200，仅 0.87x Day 200 利润，导致 Day 400 即全满。

## 参数敏感性一览

| 参数 | 调整幅度 | 对人口的影响 | 结论 |
|------|----------|-------------|------|
| 标准 scale 4→7 | +75% | 552→467 (-15%) | 有效但有限 |
| 标准 scale 4→8 | +100% | 552→29 (-95%) | 崩盘阈值 |
| K scale 4→5 | +25% | 460→16 (-97%) | **住房最敏感** |
| H scale 7→9 | +29% | 460→16 | 同上 |
| 科技除数 12→9 | +33% 耗时 | 467→460 (-2%) | 隐性但重要 |
| 科技除数 12→6 | +100% 耗时 | 467→54 (-88%) | 临界点 |
| 后期 tier 1.0→1.5 | L11+ +50% | 467→460 (-2%) | 边际效果 |
| 早期 tier 1.0→0.7 | L1-5 -30% | 460→552 (+20%) | 反而更满 |

### 核心发现

1. **住房成本是单点瓶颈**。K（月面王城）从 scale=4 调到 5（仅 +25%），人口从 460 崩到 16。人口增长完全依赖于住房建筑的可负担性。

2. **科技成本是隐形调速器**。研究耗时 +33% 不会直接体现为"造不起"，但会延迟关键解锁，级联影响全局进度。超过 +100% 则系统级崩溃。

3. **线性尺度下"前期便宜后期贵"的空间极小**。纯线性公式中，L1:L15 的成本比固定为 1:7.5。加后期 tier 1.5x 只能将 L15 提到 L1 的 11.25 倍，效果有限。要更大斜率必须引入非线性（用户明确不用）或提高初始资源配给。

4. **0.5x 早期折扣是陷阱**。曾让早期成本比原版还便宜，殖民地加速雪崩，Late tier 形同虚设。

5. **分段 tier 必须精准**。住房 scale 从 4→5 的 25% 增幅在 L1-5 段（tier 1.0）就会放大，因为早期住房瓶颈最敏感。tier 系统应与 scale 联动考虑。

## 最终效果

1000 御日无事件模拟，4 难度各 1 轮（`npm run simulate`）：

| 指标 | easy | normal | hard | ultimate |
|------|:---:|:---:|:---:|:---:|
| 最终人口 | 552/552 | 552/552 | 552/552 | 552/552 |
| 开工/完工 | 167/167 | 146/146 | 137/137 | 133/133 |
| 星舰胜利日（目标） | 581（500） | 未完成（650） | 未完成（800） | 未完成（950） |
| 合金 Day 1000 | 168094 | 119556 | 120143 | 107164 |
| 满员天数 | 470 | 478 | 486 | 483 |
| 紧张天数 | 0 | 2 | 1 | 4 |
| 最低氧气 | 0.00 | -94.33 | -82.74 | -82.83 |
| 最低生物质 | 0.00 | 0.00 | -11.93 | -195.82 |

修复优化器缺陷后（见下节），生命维持崩溃基本消除、人口全难度打满，
但暴露出更深的问题：**殖民地把合金堆到 10~17 万，同时水与生物质长期贴在 0**。
优化器只会为「建造成本」卖出盈余，不会为工程阶段的持续性物资缺口卖出盈余，
因此星舰在 normal 及以上难度无法完工。这是待新优化器解决的核心课题，
而非成本参数问题——按贸易价折算，可持续的星舰推进速度约 4.3 参考日/日，
2700 参考日的总工程量约需 630 日，与 normal 的 650 日目标本就吻合。

## 已修复的优化器缺陷

| 缺陷 | 后果 |
|------|------|
| `selectProductionMethod` 拒绝 `autoSelect: false` 的显式指定 | R 的 `MR-2/3/4` 永远回落到 `MR-1`，生态环永久烧材料且永不回报 |
| `computeSinkReadiness` 以储备线（常数 10 量级）为分母 | 就绪度恒为 1，D/R 减速从未生效，满员时日耗达产能的 4~9 倍 |
| `assignStaffingByRating` 给零分/负分岗位兜底填人 | 物资枯竭后工程设施仍被塞满，持续透支到债务上限 |
| 电力边际权重可归零 | 发电厂（唯一产出是电力）评分归零被整批撤人，电网崩塌 → 优化器进入 manual 模式全局停摆 |
| 知识权重仅在「整棵科技树点完」时归零 | 研究每日仅能吸收 10 点，L 满级产 265 点，堆出 5 万点废库存 |
| `evaluateMethod` 要求 `currentAssigned > 0` | 人力依赖方法评分、方法评分依赖人力 → 空转实验室永不切 `ML-2`，永无量子核心，星舰三阶段死锁 |
| `projectStaffing` 未含本次动作解锁的建造许可 | 新设施投影产出为空、评分为 0，配合上述规则后永远无法首建 |
| `process.env.PROFIT_BASE` 在浏览器无 `process` | 打包后读取 `{}.PROFIT_BASE`，已加运行环境判断 |

## 进一步收紧的方向

1. **提高初始资源**，使 colony 能承受更高 scale。例如初始合金 14→60 可将标准 scale 从 7 提到 10+。
2. **引入中后期 scale 分段**（L6-10 用 1x，L11+ 用 2x），配合更高初始资源。
3. **将人口建筑成本与容量直接挂钩**：`K cost = base × (level+1) × capacityPerLevel`，让住房成本自然反映其价值。
